# astrbot_plugin_bilibili_live_mod

**B 站直播弹幕机器人**：接收直播间消息（弹幕、礼物、醒目留言等），交给大模型（LLM）生成回复，再把回复**以弹幕形式发回直播间**。向 AstrBot 侧（QQ 群等）的消息转发仅用于开播/下播提醒和机器人测试。

本插件是 [astrbot_plugin_bilibili_live](https://github.com/Raven95676/astrbot_plugin_bilibili_live) 的魔改维护版，内置 blivedm 已跟进上游 v1.1.7。本插件所使用的 blivedm 经过二次开发，如有问题请勿直接向 blivedm 原作者提交 issue。

## 安装

1. 下载本插件的 zip 包，在 AstrBot 管理面板中选择"安装插件"，或放入 AstrBot 的插件目录。
2. 重启 AstrBot（或重载插件）。首次加载时会自动安装依赖（`aiohttp`、`Brotli`、`pure_protobuf`），请保持网络畅通。
3. 在插件列表中找到本插件，点击配置，按下文填写。
4. 保存配置后重启插件，观察日志确认连接成功。

## 接入方式（二选一）

插件支持两种接入方式，**同一时刻只能启用一种**；两个都启用时以 Web 接入为准。

### 方式一：Web 接入（弹幕机器人必选）

模拟浏览器连接直播间弹幕服务器。**只需要一个 B 站账号，不需要申请任何资质**。**弹幕机器人模式只能选这种方式**——发送弹幕依赖 cookie 登录态，开放平台接入方式发不了弹幕。

需要准备：

**① 直播间 ID**：打开目标直播间，地址栏 `https://live.bilibili.com/12345678` 中的 `12345678` 就是直播间 ID（填短号也可以）。

**② 三项 Cookie**（配置界面中分三个输入框分别填写）：

| 配置项 | 用途 | 不填的后果 |
| --- | --- | --- |
| `SESSDATA` | 账号登录凭证 | 能收弹幕，但用户名打码、用户 ID 显示为 0；**发送弹幕必须填** |
| `buvid3` | 设备标识 | 日志提示 `Missing buvid`，可能影响连接 |
| `bili_jct` | CSRF 凭证 | **发送弹幕必须填**，缺失时弹幕发送器拒绝启动 |

获取方法（以 Chrome / Edge 为例）：

1. 浏览器登录 bilibili.com。
2. 按 `F12` 打开开发者工具，切换到"**应用 / Application**"选项卡。
3. 左侧展开"**Cookie**"，点击 `https://www.bilibili.com`。
4. 分别找到 `SESSDATA`、`buvid3`、`bili_jct` 三行，复制各自的"值"填入对应输入框（**不要勾选"显示已解码的网址"**）。

> **安全提醒**：`SESSDATA` 相当于你 B 站账号的登录凭证，拿到它的人可以登录你的账号。请妥善保管，不要提交到公共仓库或发给别人。

### 方式二：开放平台接入（官方 API）

B 站官方[直播开放平台](https://open-live.bilibili.com/)的正规接入方式，数据更完整（用户 ID 不打码），但需要**申请开发者资质并创建项目**，适合主播本人。创建项目后获得四项信息：`access_key_id`、`access_key_secret`、`app_id`、`room_owner_auth_code`（主播身份码），填入对应配置即可。

## 配置说明

### 弹幕机器人（主模式）

`work_mode` 选 `danmaku_bot` 即启用弹幕机器人：弹幕 → LLM 生成回复 → 以弹幕发回直播间，并同步转发一份到 `forward_destinations` 便于观察。

关键配置（均在"插件设置"组）：

| 配置项 | 说明 |
| --- | --- |
| `trigger_prefix` | 弹幕触发前缀。填 `#问 ` 则只有 `#问 今天吃什么` 这类弹幕触发回复。**强烈建议设置**，留空则所有弹幕都触发，活跃直播间会挤爆发送队列 |
| `persona_prompt` | 机器人人设提示词（谁、什么性格、怎么说话），作为 system prompt 注入 LLM。插件会自动追加输出规则约束回复为短弹幕，无需重复写。写得越短越省 token |
| `llm_provider_id` | 下拉选择本插件使用的模型供应商（列出 AstrBot 中已配置的全部供应商）。留空则跟随 AstrBot 当前使用的供应商 |
| `llm_chat_max_context` | 上下文记忆轮数，实际保存条数为该值 × 2。弹幕互动是短平快场景，调到 3~5 可显著省 token |
| `allow_message_type` | 允许处理的消息类型，英文逗号分隔，可选：`danmaku, gift, guard_buy, super_chat, like, enter_room`。弹幕机器人建议只留 `danmaku` |

插件会缓存重复弹幕的回复直接复用（不消耗 token），改了人设后重载插件即可清空缓存。

插件连接弹幕前会自动通过 cookie 识别机器人账号（日志显示"已获取机器人账号: 昵称(mid)"），之后：

- **以该账号身份进入直播间**：连接弹幕时自动进房上报，并按 B 站现行 X25Kn 协议周期性上报在线心跳（与浏览器打开直播间的行为完全一致），直播间的在线观众列表中可以看到机器人账号；断开连接或下播时自动退出，无需额外配置；
- **自动忽略该账号发送的消息**——机器人不会回复自己发的弹幕。

以上均无需额外配置。如果日志出现"获取机器人账号信息失败"，说明 `SESSDATA` 未填写或 cookie 已过期，此时插件以匿名方式连接：能收弹幕，但直播间里看不到机器人账号、用户名打码，也无法过滤自己的弹幕——重新复制 cookie 即可恢复。

### 弹幕发送（`danmaku_send` 组）

| 配置项 | 说明 |
| --- | --- |
| `min_interval` | 两条弹幕的最小发送间隔（秒），默认 1.5。过快会被 B 站拒绝（错误码 10031）甚至禁言 |
| `max_length` | 单条弹幕最大长度（字），默认 40，超出截断。上限与账号等级相关，低等级账号建议填 20 |

发送按队列逐条进行，队列上限 50 条，满了新回复会被丢弃并记日志。

### 开播监控（`live_monitor` 组，仅 Web 接入支持）

开启后插件不常驻直播间：检测到开播才进房连接弹幕，下播自动断开，可降低风控风险。

| 配置项 | 说明 |
| --- | --- |
| `enable` | 是否启用，默认关闭 |
| `poll_interval` | 开播检测间隔（秒），默认 30，建议 15~60 |
| `notify_destinations` | 开播/下播通知推送目标，填 umo（在目标会话发送 `/sid` 获取），可填多个。通知为纯文本「【B站直播】开播啦！/ 主播已下播」。QQ 官方机器人通道可用，但主动推送有平台配额限制 |

注意：主播"轮播中"（放录像）视为未开播，不会进房。

### 四种工作模式

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| `danmaku_bot` | AI 回复以弹幕发回直播间，并同步转发到 `forward_destinations` | 主模式 |
| `forward_only` | 直播间消息原样转发到 AstrBot 侧 | 测试弹幕接收 |
| `llm_chat_forward` | AI 回复只转发到 AstrBot 侧，不发弹幕 | 开播前调试 AI 回复效果 |
| `llm_chat_callback` | AI 回复请求自定义回调接口（POST JSON 或 GET 参数，字段为 `sender`、`sender_name`、`message`） | 接入自有系统 |

除 `forward_only` 外的模式都需要 AstrBot 已配置可用的 LLM 供应商。`random_drop`（随机丢弃）用于测试丢消息场景，不确定时保持关闭。

转发到 AstrBot 侧的消息格式：`[弹幕] 张三(12345678)说: 主播好强`，礼物/醒目留言/点赞/进场/上舰类推。

## 弹幕发送的风控须知

**收弹幕只是"看"，发弹幕是"动手"**，操作对象是 cookie 对应的 B 站账号：

1. **强烈建议使用小号发送**。频率失控或内容违规会被禁言甚至封号。
2. **务必设置 `trigger_prefix`**，让机器人只回特定弹幕。
3. **不要调低 `min_interval`**。1.5 秒是社区验证过的安全间隔。
4. **注意账号等级**。低等级账号上限 20 字，把 `max_length` 改成 20。
5. **AI 回复内容不可控**。先用 `llm_chat_forward` 模式观察一段时间再切换到 `danmaku_bot`。
6. 开播监控 + 弹幕机器人可叠加使用：开播才进房、进房才发弹幕，减少账号在线时长。

## 常见问题

**插件没有任何消息转发出来**
- 确认只启用了一种接入方式且 `enable` 为 `true`；确认 `allow_message_type` 包含你期待的消息类型。
- 开了开播监控时，主播没开播就没有消息，属正常现象；看日志有没有"已开播，开始连接弹幕"。
- Web 接入：确认直播间 ID 正确、房间正在直播；日志出现 `Missing buvid` 说明 `buvid3` 没填。

**开播/下播通知没推送到群里**
- 确认 umo 是在**目标群**里用 `/sid` 获取的（私聊和群聊的 umo 不一样）；查看日志里的"推送通知失败"报错。

**弹幕用户名打码 / 用户 ID 是 0**
- `SESSDATA` 缺失或已过期，重新登录 bilibili.com 复制。

**直播间里看不到机器人账号进入**
- 确认日志里依次出现"已获取机器人账号: 昵称(mid)"、"机器人账号已进入直播间 xxxx"和"直播间在线心跳已建立（服务端间隔 Ns）"。第一条缺失说明 `SESSDATA` 未填或已过期；心跳未建立则把日志中的警告反馈给插件作者。
- 在线状态由 X25Kn 心跳维持（间隔由 B 站服务器下发，约 60 秒），主播刚开播或网络波动时在线列表更新可能有短暂延迟。

**LLM 模式报错"没有可用的模型供应商"**
- 确认 AstrBot 的模型供应商配置里至少有一个 `enable` 为 `true` 且密钥有效；如果下拉选择了供应商，确认该供应商未被停用。

**机器人不发弹幕 / 弹幕发不出去**
- 日志找"弹幕发送失败"对照错误码：`-101` SESSDATA 过期；`-111` 缺 `bili_jct` 或已过期；`10031` 发送过快（调大 `min_interval`）；`1003212` 超长（`max_length` 调到 20）。
- 确认 `work_mode` 是 `danmaku_bot` 且启用了 Web 接入；日志出现"弹幕发送器初始化失败"说明缺 `SESSDATA` 或 `bili_jct`。
- 设了 `trigger_prefix` 时，不带前缀的弹幕不会触发回复。

**弹幕回复要等很久才发出来**
- 发送是排队限速的（默认每条 1.5 秒），触发太频繁会积压，队列满 50 条后丢弃。解决：收窄 `trigger_prefix`，或 `allow_message_type` 只保留 `danmaku`。

**AI 回复太书面、太长或不像人设**
- 把 `persona_prompt` 写得更具体（说话风格、口癖）；先用 `llm_chat_forward` 模式观察效果，满意后再切 `danmaku_bot`。

**连接偶尔断开**
- 长连接偶尔掉线属正常，插件会自动重连（连续失败超过 10 次停止并记日志），一般无需干预。
